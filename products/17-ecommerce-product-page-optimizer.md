## Page structure
### 1. Headline
Describe the product and primary use case clearly.

### 2. First paragraph
State who it is for, what it helps them do, and what is included.

### 3. Benefits linked to features
| Feature | Practical benefit | Evidence / demo |
|---|---|---|
| | | |

### 4. Contents
List every file, format, version and bonus. Do not imply files exist if they do not.

### 5. Fit and non-fit
**Good fit if:** [conditions]  
**Not a fit if:** [conditions]

### 6. Objections
| Buyer question | Honest answer | Evidence |
|---|---|---|
| Does it work with…? | | |
| What do I receive? | | |
| Is support included? | | |
| Can I use it commercially? | | |

### 7. Call to action
Use one clear next step. Avoid fake scarcity or unsupported urgency.

## Visual asset checklist
- [ ] Main cover shows the actual product
- [ ] Preview screenshots are legible
- [ ] No fake testimonials or sales numbers
- [ ] Fonts and images are licensed
- [ ] Mobile crop checked
- [ ] File formats and dimensions stated

## Page QA
- [ ] Price and currency correct
- [ ] Download attached and tested
- [ ] Description matches delivered file
- [ ] Refund and support terms clear
- [ ] Links work
- [ ] No unsupported guarantees
- [ ] Product category and tags are relevant
